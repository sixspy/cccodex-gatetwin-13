# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
# 再灌「半截装载回滚样例」→ 看批失败闭（整批回滚，A 的行程也没了）
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 |
| 批失败闭 | 装载批中途撞未知站时的失败闭口（只读） |

## 半截装载回滚（整批回滚口径）

本仓全局选定 **整批回滚**，不再保留另一种口径：

- 装载批中途撞上**未知站点** → 本批**所有卡**已写入的刷卡点 / 开腿账 / 行程账 / 旁路匣
  一律回滚到批前；批报告 `成功=false`、`结果=失败`，不得报告成功却留脏行程。
- 失败闭只读接口：`GET /api/批失败闭/{batch_id}`（列表 `GET /api/批失败闭`），
  字段：批次编号、肇事卡、保留行程数、回滚范围标记、`valid`。
- `valid`：按整批回滚口径复核该批在四本账上是否一条不剩、保留行程数是否为 0。

对照口径「肇事卡隔离回滚」（本仓**不采用**）：仅回滚肇事卡、保留其他卡已成对行程、
批报告部分成功。两口径下「卡A成对后卡B遇未知站」时 A 的行程是否仍在会分叉
（甲：A 行程也没了；乙：A 行程仍在且 B 旁路），故必须全局只贯彻一种。

事务：`BEGIN IMMEDIATE` 取写锁 + 批内 `SAVEPOINT`；失败时 `ROLLBACK TO` 回滚本批，
在同一写事务内落失败闭与失败批报告。并发第二批被写锁挡住，不会读到半截开腿。

夹具（`fixtures/`）：`半截装载回滚样例`（A成对后B未知站，应整批回滚）、
`半截装载回滚样例2`（A成对后B出站未知站，应整批回滚）、`纯成功多卡样例`（全成对）、
`并发失败批` / `并发出站批`（并发第二批不得读半截开腿）。
